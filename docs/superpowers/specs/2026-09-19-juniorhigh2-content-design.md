# 中2コンテンツ 指導要領網羅（Phase A）設計書

- 日付: 2026-09-19
- 対象: AI先生（`Y:\AI先生`）／ブランチ `feature/juniorhigh-content`
- 位置づけ: 大目標「中2＝学習指導要領を網羅／全単元ランダム出題／その後 中1」の **Phase A（中2コンテンツ網羅）**。
  - Phase B（テストの全教科対応＋全単元ランダム）と Phase C（中1）は別サイクル。

## 1. 目的

中2の各教科を、学習指導要領の主要単元まで問題を増やし、「これ一個で中2の学習を網羅」できる状態にする。**生成AIは採点・事実生成に使わない**（数学＝コード生成で答え確定、クイズ＝authored＝人手相当で確定＋事実監査）。

## 2. 前提・既存パターン（踏襲）

- **数学**: `src/lib/math/` に単元定義ファイル（`units.ts` / `units_b.ts` / `units_c.ts` / `units_j2.ts`）。各 `UnitDef` は
  `{ id, grade, title, lesson, answerType, hint, generate(): Problem, diagnose?(problem,userInput): string|null }`。
  `Problem = { unitId, prompt, answer, answerType, choices?, meta? }`。`math/index.ts` の `ALL_DEFS` に配列を連結して集約。**問題も答えもコードで生成・確定**、誤答は `meta` からルール診断。
- **クイズ（理社国英）**: `src/lib/quiz/` にバンクファイル（`*_j2.ts`）。各 `QuizUnit = { id, subject, grade, title, lesson?, items: QuizItem[] }`。
  `QuizItem = { id, question, choices: string[], answerIndex, explanation, choiceHints?: (string|null)[] }`。`quiz/index.ts` の `QUIZ_UNITS` に連結。**選択式・正解はコード固定・index採点・解説はauthored**。
- 現状の中2: 数学8単元（`units_j2.ts`）／理科36・歴史36・地理36・国語36・英語48問（`*_j2.ts`）。
- 学齢・学年は既存の `Grade`（"中2"）を使う。テスト/練習UIは学年で単元を出し分け済み。

## 4. ファイル構成（新規は _d サフィックスで増設、既存は不変）

- 数学: `src/lib/math/units_j2d.ts`（中2追加分 UnitDef 配列 `UNIT_DEFS_J2D`）を新規作成し、`math/index.ts` の `ALL_DEFS` に連結。既存 `units_j2.ts` は不変。
- クイズ: 各教科の追加分を新規ファイルに:
  `science_j2d.ts` / `history_j2d.ts` / `geography_j2d.ts` / `japanese_j2d.ts` / `english_j2d.ts`（各 `*_UNITS_J2D` 配列）。`quiz/index.ts` の `QUIZ_UNITS` に連結。既存 `*_j2.ts` は不変。
- 1エージェント＝1ファイル（=1教科の追加分、または数学の1グループ）で並列量産し、監督（コントローラ）が index で束ねる。

## 5. 品質基準（ゲート）

- **id 一意**（既存 id と衝突しない。`j2d-*` / `<subj>-j2d-*` 接頭辞）。`answerIndex` 範囲内。choices 重複なし。
- **数学**: 各 def が自己検証（≥1000ケースで `generate()` の答えを独立ロジックで再計算し一致）。`diagnose()` はありがちな誤答を meta から再現。
- **クイズ**: **独立の事実監査レビュー**を教科ごとに実施し、事実誤り（Blocker）ゼロになるまで反復。特に国語（文法・古典）・社会（年号・人物）。曖昧・出典不確かな問題は落とす。
- `npm run build` 緑 / `npx tsc --noEmit` 緑 / 既存 Vitest 緑を維持。集約後に「id重複0・answerIndex範囲0・件数」を機械監査。
- **生成AIは不使用**（採点・事実生成に使わない）。

## 6. 実行方式（Phase A）

1. `superpowers:dispatching-parallel-agents` で教科ごとに authoring エージェントを並列起動（数学は生成ロジック担当、理社国英は authored バンク担当）。各エージェントは §3 の担当単元・§2 のスキーマ・§5 の品質基準に従い新規ファイルを作成し自己検証。
2. コントローラ（私）が `index.ts` で束ね、機械監査（id重複/範囲/件数）＋build/tsc/test。
3. 教科ごとに **事実監査エージェント**を独立起動し、Blocker ゼロまで反復修正。
4. 全教科そろったらまとめてコミット（教科単位で小分けコミット）。
